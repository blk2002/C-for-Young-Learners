## 1. 项目概述

### 1.1 背景与目标

小程序目前的课程内容（学科 → 章节 → 知识点）与题库（学习题 / 章节习题 / 考试题）依靠 `initCourses` / `initQuestions` 云函数硬编码初始化，或在手机端 admin 管理页逐题填写，维护成本高。

本工具提供一个**网页版工作台**，让老师在电脑上完成：

1. 课程结构的建立与维护（章节、知识点）
2. 知识点速记内容（概念 / 特征 / 易混淆 / 代码）的编写
3. 三类题目的批量导入、AI 生成与校对
4. 一键同步到云数据库，小程序端立即可见

### 1.2 使用者与开源定位

- 当前仅本人使用；做完后将工具包与方法步骤开源分享
- 复刻者只需：一个微信小程序云开发环境 + 一台普通电脑（8~16GB 内存、无独立显卡亦可）
- 全流程不依赖付费云端 API，AI 理解环节使用免费网页 AI，格式转换环节使用本地 Ollama 模型

### 1.3 与小程序的关系

**零改动原则**：工作台只向现有云数据库集合写入符合现有结构的数据，小程序端页面、现有云函数一律不改。

唯一例外：**新增学科**需要在小程序 `app.js` 的 `globalData.courses` 中同步添加配置（一次一行），文档中明示。

## 2. 总体架构（已选定方案 C）

### 2.1 架构组成

```
┌─ 浏览器（老师电脑）─────────────────────┐
│  工作台网页（静态托管于云开发）           │
│  ├─ 素材粘贴 / Word、TXT 解析            │
│  ├─ 调本地 Ollama（localhost:11434）     │
│  ├─ 草稿树编辑 + 校对                    │
│  └─ @cloudbase/js-sdk 匿名登录           │
└──────────────┬──────────────────────────┘
               │ 调云函数
┌─ 微信云开发环境 ─▼───────────────────────┐
│  云函数：importContent / getCourseTree   │
│  数据库：chapters / lessons /            │
│         chapterQuestions / examQuestions │
└──────────────┬──────────────────────────┘
               │ 学生刷题
        小程序端（不改）
```

三个组成部分：

| 组成 | 位置 | 作用 |
|---|---|---|
| 静态网页 | 云开发静态托管，正式网址 `https://xxx.tcloudbaseapp.com` | 全部操作界面 |
| 本地模型 | 老师电脑上的 Ollama（qwen 4B 级量化模型） | 素材 → 结构化 JSON 的格式转换、题目现编 |
| 云开发 | 现有环境 cloud1-d5g4wtnsn6cc1b835 | 新增 2 个云函数 + 复用 4 个现有集合 |

### 2.2 数据流总览

```
网上找教程/题库
   →（免费网页 AI：豆包/Kimi/DeepSeek 网页版，人工复制粘贴）
半结构化素材文本（按素材模板）
   →（粘贴或拖文件进入工作台）
本地 Ollama 按模板纠偏转换
   → 结构化草稿（工作区内可编辑）
人工校对（手动改 + AI 结果改，同一棵树）
   → 同步（匿名登录调云函数，写入 4 个集合）
小程序学生端立即可见
```

### 2.3 关键设计决策记录

| 决策点 | 选择 | 理由 |
|---|---|---|
| 网页放哪 | 云开发静态托管（方案 C） | 正式网址天然满足 Web 安全域名；本地 localhost 路线存在安全域名不确定性，被否决（方案 A） |
| 要不要 Node 后端 | 不要（否决方案 B） | 复刻者需会命令行 + 管理云密钥，与开源定位冲突；纯静态页复刻门槛最低 |
| AI 分工 | 网页 AI 产素材 + 本地 4B 模型做格式转换 | 4B 模型理解杂乱长文能力弱，但按模板转换可靠；人工校对兜底 |
| 入库方式 | 网页匿名登录调云函数 | 免密钥管理；云函数内校验管理密码 |
| 内容顺序 | 先结构后题目 | 题必须挂在已存在的知识点上；题目素材又来自知识点内容本身 |
| 题库去重 | 题干+答案归一化哈希 | 防止重复导入 |

## 3. 技术选型

| 项 | 选择 | 说明 |
|---|---|---|
| 页面形态 | 单文件 `index.html`（原生 HTML/CSS/JS，无构建） | 双击可本地预览，部署即传一个文件；复刻者零门槛 |
| 云端 SDK | `@cloudbase/js-sdk`（CDN 引入） | 匿名登录 + 调用云函数 |
| Word 解析 | `mammoth.js`（CDN） | docx → 纯文本；PDF 不支持（解析脆，明示） |
| TXT 解析 | 原生 `FileReader` | 直接读文本 |
| 本地模型 | Ollama REST API（`http://localhost:11434`） | 模型建议 `qwen3:4b` 或 `qwen2.5:3b` 量化版，约 2~3GB |
| 跨域 | Ollama 启动参数设 `OLLAMA_ORIGINS=*`（工具包提供 .bat） | 允许 HTTPS 云端页面访问 localhost |
| 本地暂存 | `localStorage` | 草稿不丢失（刷新页面保留），可一键清空 |

## 4. 数据模型

### 4.1 现有云数据库集合（写入目标，结构不变）

| 集合 | 字段 | 说明 |
|---|---|---|
| `chapters` | `courseId, title, order, createdAt` | 章节 |
| `lessons` | `chapterId, title, content, codeExample, order, questions` | 知识点；`questions` 为学习题数组或 null |
| `chapterQuestions` | `courseId, chapterId, lessonId, questions, createdAt, updatedAt` | 按知识点 upsert（一组一条文档） |
| `examQuestions` | `courseId, examType, level, questions, createdAt, updatedAt` | 按考试类型+级别 upsert |

题目对象两种：

```js
// 选择题
{ type: 'choice', question, options: { A, B, C, D }, answer: 'B', explanation }
// 填空题
{ type: 'fill', question, answer, explanation }
```

取值约定：
- `courseId`：现有 `python` / `cpp`；新增学科需同步 `app.js`
- `examType`：CIE / GESP / CSP-J（以库内存量为准，工具用下拉选择）
- `level`：级别（如 一级、二级、入门级），下拉选择，允许新增值

### 4.2 三段速记与 content 的映射

小程序学习页把 `lessons.content` 当纯文本渲染。为保证零改动：

- 工作台编辑区分【概念】【特征】【易混淆】三段 + 代码块
- 同步时合成为单个字符串：

```
【概念】……
【特征】……
【易混淆】……
```

- 代码示例仍写入独立的 `codeExample` 字段（现有行为）
- 从云端拉取时按 `【xx】` 标记反向拆分回三段编辑框；无标记的旧内容整体放入【概念】段

（未来小程序端可选择解析这些标记做样式化渲染，属于可选增强，不在本期范围。）

### 4.3 工作台草稿模型（localStorage）

```js
draft = {
  version: 1,
  savedAt: '...',
  password: '(管理密码，仅存本机)',
  tree: {
    python: {                     // courseId
      name: 'Python',
      chapters: [
        {
          key: 'c-1694...',       // 前端生成的临时 key
          title: '第1章 …',
          order: 1,
          cloudId: '已有章节的_id 或 null',   // null = 本次新增
          lessons: [
            {
              key: 'l-1694...',
              title: '1.1 …',
              order: 1,
              cloudId: null,
              chapterKey: 'c-1694...',
              content: { concept, feature, confusion },
              codeExample: '...',
              questions: [ /* 学习题 */ ],
              contentDone: true   // 三段齐全视为完成
            }
          ]
        }
      ]
    }
  },
  chapterQuestions: [ /* 待同步的章节题（带 lessonKey 归属） */ ],
  examQuestions: [ /* 待同步的考试题（带 examType/level） */ ]
}
```

## 5. 素材模板规范

模板是「网页 AI 输出」与「本地模型解析」之间的契约。工作台内置「复制模板」「复制给网页 AI 的指令」按钮。

### 5.1 模板语法

```markdown
# 学科：Python
## 第1章 认识 Python 与第一个程序
### 知识点：1.1 什么是编程与 Python
【概念】（≤60 字，一句话说清是什么）
【特征】（≤60 字，判断要点）
【易混淆】（≤60 字，最常混的 1~3 组对比）
【代码】（最小示例，可为空）
【学习题】
- 选择|题干|A:选项A|B:选项B|C:选项C|D:选项D|答案:B|解析:…
- 填空|题干|答案:xxx|解析:…
【章节题】
- 选择|…（同上格式）
【考试题】(GESP,一级)
- 选择|…（同上格式）
```

规则：
- 层级固定三层：`#` 学科 → `##` 章节 → `###` 知识点，不引入更深层级
- 三段标记缺任一段 → 该知识点标"待补"，不阻塞其他内容
- 题目行固定以 `选择|` 或 `填空|` 开头，字段用 `|` 分隔
- 考试题的归属标注 `(考试类型,级别)`，如 `(GESP,一级)`、`(CSP-J,入门级)`

### 5.2 容错规则（本地模型纠偏范围）

网页 AI 输出难免跑偏，本地模型负责在以下范围内纠偏，超出则标"待处理"：

| 跑偏情形 | 纠偏动作 |
|---|---|
| 层级符号多一级（`####`） | 归入最近的知识点内容 |
| 三段标记写成 `概念:`、`**概念**：` | 识别为同义标记 |
| 题目行用 `A.xxxx` 或 `A、xxxx` | 统一为 `A:xxxx` |
| 答案写成 `答案：B`（全角冒号） | 统一半角 |
| 章节编号与顺序不符 | 按【代码】出现顺序取 order |
| 无法解析的行 | 原文放入"待处理"列表，不硬猜 |

## 6. 功能清单（操作级说明）

页面为单页应用，顶部四个区域：**连接状态条 → 模式页签（① 结构与内容 / ② 题目）→ 左侧结构树 + 右侧工作区 → 底部同步栏**。

### F0 连接与状态

- 打开页面自动检测两项连接：
  - 云端连接：匿名登录是否成功（成功后可拉取/同步）
  - 本地模型：`GET localhost:11434/api/tags` 是否响应（显示模型名）
- 本地模型未连接：顶部黄条提示「双击工具包内 `启动本地模型.bat`」，AI 按钮置灰；校对、云端拉取、同步不受影响
- 云端未连接：红条提示检查网络与匿名登录配置；同步按钮置灰
- 首次使用引导输入**管理密码**（存 localStorage，可修改）

### F1 结构树手动管理（不依赖 AI）

| 操作 | 入口 | 行为 |
|---|---|---|
| 新建学科 | 树根「＋学科」 | 输入名称，生成 course 配置（下拉沿用 python/cpp 已有 id，新 id 提示需同步 app.js） |
| 加章节 | 学科行「＋章节」 | 行内输入标题，追加到该学科末尾 |
| 加知识点 | 章节行「＋知识点」 | 行内输入标题，追加到该章末尾 |
| 重命名 | 节点「✎」 | 行内编辑标题 |
| 删除 | 节点「✕」 | 二次确认；删除章节级联标记其下知识点；已入库节点同步时执行云端删除 |
| 排序 | 拖拽节点 | 同级内上下拖动，order 自动重算 |
| 折叠/展开 | 章节行「▾」 | 收起/展开知识点列表 |
| 状态标记 | 节点右侧图标 | 绿✓=内容完成；黄!=三段缺失；灰○=新增未入库 |

### F2 素材输入

- 两种输入：粘贴文本（大文本框）/ 拖入文件（Word .docx、.txt；其他格式提示不支持）
- 文件解析在前端完成（mammoth/ FileReader），只取纯文本
- 输入区实时统计：字数、按模板预估的章节数/知识点数
- 「清空」按钮一键重置

### F3 AI 整理（两种模式）

- **整树模式**（阶段②用）：把整份素材一次性转成完整草稿——结构树 + 三段内容 + 三类题目（按模板标记各自挂到草稿对应位置）。解析前可设置"学科缺失时默认学科"。题目虽在此时已入草稿，但入库仍受两阶段顺序约束（见 F6）
- **填空模式**（选中单个知识点时）：只解析三段内容+代码，填充当前选中知识点，不动结构
- 解析过程显示进度（按知识点分块调用本地模型，每块一个请求，避免超长上下文）
- 解析结果进入草稿树（与手动编辑同一棵树），全部标"新增/待改"，等待校对
- 解析失败的块重试一次，仍失败进入"待处理"列表

### F4 知识点内容编辑

- 选中知识点 → 右侧四个编辑框：【概念】【特征】【易混淆】【代码】
- 每段实时字数显示；>60 字黄底提示"建议裁剪"（软限制，可继续）
- 「拆分云端旧内容」：拉取后旧 content 无标记时，整段入【概念】，可手动剪贴到其他段
- 编辑即存草稿（localStorage 自动保存）

### F5 题目管理（阶段③）

- 前置：所选知识点 `contentDone` 为真，否则提示"先完成知识点内容"
- 三种来源：
  1. **粘贴题目素材**：按模板题行解析（含【学习题】【章节题】【考试题】标记）
  2. **基于知识点现编**：本地模型读该知识点的三段速记（重点【易混淆】）生成 N 道题（N 可选 2/3/5）
  3. **手动加题**：「＋题目」按钮，表单逐题填写
- 归属匹配：素材中未标归属的题，本地模型按题干 ↔ 知识点概念匹配给出建议挂载点，状态标"待确认"；用户点开下拉改
- 逐题校对表格：行内可编辑题型/题干/选项/答案/解析/归属；单行删除；单行"标记跳过"
- 硬校验（不通过不能同步，标红）：
  - 选择题必须 A~D 四项齐全、答案 ∈ ABCD
  - 填空题答案非空
  - 归属知识点必须存在
- 去重（软提示，可强行导入）：与云端拉取的已有题对比"题干去空白+答案"哈希，重复标"重复跳过"默认不导

### F6 同步入库

- 两阶段分别同步：
  - 阶段②按钮「同步结构与内容」：写 `chapters` + `lessons`（含学习题 `questions` 字段）
  - 阶段③按钮「同步题目」：写 `chapterQuestions` + `examQuestions` + `lessons.questions`（学习题在题目阶段的修改）
- 顺序约束：阶段③同步在校对通过后进行，且仅当目标知识点已入库（有 cloudId）——题目永远挂在已入库的知识点上，杜绝孤儿题；未入库知识点的题标红拦截
- 同步前弹确认清单（新增 X、更新 Y、删除 Z、跳过 W）
- 同步中显示进度；失败项逐条列出原因，可"仅重试失败项"
- 幂等：已入库的（cloudId / upsert 键）走更新，不重复创建
- 完成后显示批次报告（写入统计 + 小程序三步验证指引），并自动从云端拉取刷新

### F7 云端拉取

- 「从云端拉取」按钮：读取 4 个集合 → 反向构建树上已有数据（含 cloudId）
- 作用：校对对照、去重依据、把"新增/更新"区分开
- 拉取不覆盖本地未同步的草稿改动（仅合并已入库部分）

### F8 备份导出

- 「导出 JSON 备份」：下载当前草稿（含树+全部题目）为 `backup-YYYYMMDD-HHmm.json`
- 「导入备份」：选 JSON 文件恢复草稿（本地误删/换电脑场景）

### F9 帮助与模板

- 「复制素材模板」：得到 5.1 完整模板文本
- 「复制给网页 AI 的指令」：一段可直接粘贴给豆包/Kimi 的指令（含模板+要求按模板输出）
- 「首次使用引导」：一次性部署步骤（7.1）的内置说明页
- 「故障排查」：常见问题（本地模型未连、云端未连、同步失败）的处置说明

## 7. 详细操作流程

### 7.1 一次性部署准备（约 40 分钟，只做一次）

1. **装 Ollama**：ollama.com 下载 Windows 版安装
2. **拉模型**：命令行 `ollama pull qwen3:4b`（约 2.5GB）
3. **建启动脚本**：使用工具包 `启动本地模型.bat`（内部执行 `set OLLAMA_ORIGINS=*` 后启动 `ollama serve`），双击一次，模型常驻后台
4. **开通静态托管**：微信开发者工具 → 云开发控制台 → 静态网站托管 → 开通
5. **上传页面**：把 `index.html` 上传到静态托管根目录，得到网址并收藏
6. **开匿名登录**：控制台 → 环境 → 登录授权 → 启用「匿名登录」
7. **部署云函数**：右键 `importContent` / `getCourseTree` → 上传并部署（云端安装依赖）
8. **配置管理密码**：首次打开工作台时设置（写入云函数环境配置，见 §9）
9. **验证**：打开网址，两盏连接灯变绿即就绪

### 7.2 日常流程 A：新建课程结构（AI 路线）

1. 浏览器打开工作台网址（收藏夹）
2. 点「复制给网页 AI 的指令」
3. 把网上找到的教程内容 + 指令一起发给豆包/Kimi，得到模板化素材
4. 回到工作台，切「① 结构与内容」页签，把素材粘贴进输入框（或拖 Word/TXT）
5. 点「开始 AI 整理」→ 等待进度完成（每知识点约 10~20 秒）
6. 左侧树出现生成的结构；逐个点选知识点，检查右侧三段内容与代码，黄标项补齐
7. （可选）手动加/删/排序/改名，与 AI 结果混合编辑
8. 点「同步结构与内容」→ 确认清单 → 完成报告
9. 小程序「章节」页验证新结构出现

### 7.3 日常流程 B：补充单个知识点内容

1. 打开工作台，树上选中目标知识点
2. 把该主题的新素材粘贴 → 点「AI 整理（填入当前知识点）」
3. 检查右侧四框 → 微调 → 「同步结构与内容」

### 7.4 日常流程 C：导入题目

1. 打开工作台，切「② 题目」页签（若阶段②解析的素材已含题目，它们已出现在校对表中，可直接从第 5 步继续）
2. 树上选中目标知识点（挂载点）
3. 需要补充时选择来源：粘贴题目素材 / 现编 / 手动加题
4. 现编时选数量 → 本地模型基于三段速记生成（易混淆栏优先出对比题）
5. 表格逐题校对：改错、定归属（待确认项下拉选择）、跳过重复
6. 红色硬校验清零后，「同步题目」→ 确认 → 报告
7. 小程序「章节习题」「等级考试」验证新题

### 7.5 日常流程 D：纯手动维护（不用 AI）

1. 打开工作台 → 「从云端拉取」
2. 树上直接增/删/改/排序、编辑内容框、手动加题
3. 「同步结构与内容」和/或「同步题目」

### 7.6 故障排查

| 现象 | 处置 |
|---|---|
| 本地模型黄条 | 双击 `启动本地模型.bat`；确认 `ollama list` 有模型 |
| 云端红条 | 检查网络；控制台确认匿名登录已开 |
| AI 整理卡住 | 单知识点分块调用，看哪块失败；重试或该块手动补 |
| 同步部分失败 | 报告里点「仅重试失败项」；仍失败检查管理密码 |
| 换电脑 | 导出备份 JSON 带走；新机重装 Ollama 与网址 |

## 8. AI 提示词与校验规则

### 8.1 结构转换提示词（本地模型，整树模式）

```
你是课程结构转换器。把用户素材转换为严格 JSON。
只输出 JSON，不要解释。结构：
{
  "course": "学科名",
  "chapters": [
    { "title": "章节标题",
      "lessons": [
        { "title": "知识点标题",
          "concept": "概念，≤60字",
          "feature": "特征，≤60字",
          "confusion": "易混淆，≤60字",
          "code": "代码示例或空串",
          "questions": [
            {"type":"choice","question":"…","options":{"A":"…","B":"…","C":"…","D":"…"},"answer":"B","explanation":"…"},
            {"type":"fill","question":"…","answer":"…","explanation":"…"}
          ]
        }
      ]
    }
  ]
}
素材中的题目按标记分拣：【学习题】进所属知识点的 questions；【章节题】进 chapters 题组；【考试题】进 exams 题组（带 examType/level）。
无法识别的内容放入 "pending" 数组，原样保留文本，不要猜测。
```

### 8.2 题目转换提示词（本地模型）

```
你是题目转换器。把用户素材中的题目转换为 JSON 数组。
只输出 JSON。每题：
{"type":"choice"|"fill","question":"…","options":{…选择题必填…},"answer":"…","explanation":"…","target":"learn|chapter|exam","examType":"GESP","level":"一级"}
target 由素材标记决定：【学习题】→learn，【章节题】→chapter，【考试题】→exam（带类型级别）。
无法确定 target 时填 "unknown"，不要猜。
```

### 8.3 现编题目提示词

```
根据以下知识点速记出 N 道练习题，优先针对【易混淆】出对比题。
【概念】…【特征】…【易混淆】…
要求：题干清晰、答案唯一、解析一两句话。输出 JSON 数组（格式同题目转换器，target=chapter）。
```

### 8.4 校验规则表（同步前自动执行）

| 规则 | 级别 | 处理 |
|---|---|---|
| 三段任一为空 | 警告 | 节点标黄，可同步（content 缺段照常拼串） |
| 三段超 60 字 | 提示 | 黄底显示字数，不阻塞 |
| 选择题选项不全/答案越界 | 硬错误 | 标红禁止同步，点行跳转修改 |
| 填空答案为空 | 硬错误 | 同上 |
| 归属知识点不存在 | 硬错误 | 同上 |
| 题目重复（哈希命中） | 软 | 默认跳过，可手动改导 |
| JSON 解析失败（模型输出跑偏） | 待处理 | 原文进待处理列表，人工处理 |

### 8.5 去重哈希

`hash = 题干.trim().replace(/\s+/g,'') + '||' + 答案.trim()`，与云端拉取的题目集合对比；同知识点内也互相比对。

## 9. 云函数设计

### 9.1 新增云函数 `importContent`

- 职责：接收草稿树 diff，按 mode 写入 4 个集合；删除操作仅限显式传入的 `deleteIds`
- 入参 `mode`：
  - `structure`：写 `chapters` + `lessons`（含 `questions` 学习题）
  - `questions`：写 `chapterQuestions` + `examQuestions` + `lessons.questions`（学习题修改）；拒绝挂到未入库知识点的题
- 鉴权：入参 `password` 与云函数环境配置中的 `ADMIN_PASSWORD` 比对，失败返回错误且不写库；连续失败 5 次锁定 10 分钟（内存计数）
- 写入逻辑：
  - `chapters`：有 `cloudId` → update title/order；无 → add
  - `lessons`：同上，`content` 由三段拼串（4.2 规则），`questions` 直接覆盖
  - `chapterQuestions`：按 `(courseId, chapterId, lessonId)` upsert（复用现有逻辑）
  - `examQuestions`：按 `(courseId, examType, level)` upsert
- 返回：逐项结果（成功/失败+原因）+ 新建的 cloudId 回填，前端写回草稿
- 事务性：不追求跨集合事务，失败项可单独重试（幂等保证重复调用安全）

### 9.2 新增云函数 `getCourseTree`

- 职责：读取 4 个集合全量（个人题库量级，一次拉全），返回树 + 题目清单（含 `_id`）
- 鉴权：同样校验管理密码（防止匿名用户枚举题库）

### 9.3 不改的东西

现有 22 个云函数、全部小程序页面、现有集合的字段结构——一律不动。

## 10. 安全说明

- 匿名登录仅能调用上述 2 个云函数，且两个函数都有管理密码校验，匿名者拿不到数据
- 管理密码强度建议 ≥8 位；存于云函数环境配置（部署时设置），不进代码仓库
- 前端 localStorage 存密码明文——个人电脑场景可接受，文档中如实说明
- 不涉及学生个人信息，泄露面小
